# Vibe Space v1.0.0 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote Vibe Walls to v1.0.0 of Vibe ADE: rename the product to "Vibe Space", move the Groq proxy infra to the new Supabase project, and publish the history to the Vibe_ADE repo as branch `V1.0.0`.

**Architecture:** Work in-place in the existing `vibe-walls` working tree (reuses `node_modules` + Rust `target/` on a tight disk). Rename in three layers — identity/packaging, IPC+storage contract, agent/UI-visible strings — each committed separately. Then migrate Supabase infra, repoint the app, push to the new remote, and finally rename the folder and decommission the old project.

**Tech Stack:** Tauri 2 (Rust), React + TypeScript, Vitest, Supabase (edge functions + Postgres), Groq.

**Scope boundary (from spec):** Rename the **contract** surface (Tauri IPC command names, the on-disk `walls/` dir) and everything **user/agent-visible** (agent tool names + descriptions + return text, UI prose, packaging identity, README). Deliberately **leave internal-only identifiers** unchanged — TS types `WallMeta`/`WallDoc`, the `View` discriminator `"wall"`, persistence helper names `loadWall`/`saveWall`/`deleteWall`, the `src/wall/` module dir, `WallView`, and CSS class names (`wall-badge`, …). These are not user-visible text or a persisted/IPC contract; renaming them is churn with bug risk.

**Reference spec:** `docs/superpowers/specs/2026-06-13-vibe-space-v1-migration-design.md`
